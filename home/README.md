# home — 起動・メニュー・装置

実行ファイル `donna-iro` の本体。引数と設定を読み、装置を開き、メニューに
遊びを並べる。遊びには装置を `kit::Devices` にまとめて貸し、終われば返して
もらう。

| 層 | ファイル | 装置に触るか |
| --- | --- | --- |
| 起動 | `main.rs`、`config.rs` | 組み立てるだけ |
| メニュー | `menu.rs` | **触らない。** `kit` 越しに借りるだけなので、進行は装置なしでテストしている |
| 装置 | `io/` | ここだけが触る |

## スレッド

macOS ではウィンドウをメインスレッドに置く必要がある。しかも
`cpal::Stream` も `rodio::OutputStream` も `!Send` で、作ったスレッドから
動かせない。そこで**遊びをワーカースレッドに出し、メインスレッドは描画に専念**する。
再生や認識でウィンドウが固まらない。

**装置は開き直さない。** マイクと whisper の初期化に秒単位かかるので、
起動時に1度だけ開き、どの遊びにも同じものを貸す。

## メニューと「もう1回」

「もう1回」を待つところは、遊びとは逆に**無反応を「終わり」と読む。**
遊びのループの外なので、黙っていることは続ける意思が無いことと同じ。

| 決めごと | 理由 |
| --- | --- |
| 待ちは**声では受けない** | 歓声や物音で勝手に再開してしまう。続けるかを決めるのは親 |
| 遊びの絵を暗くしたまま、真ん中に「もう1回」のボタンを出す | 続きがあると見せるため。真っ暗にすると終了に見える |
| ボタンは絵記号ではなく字で書く | 押すのは子どもではなく親だから |
| ボタンは**当たり判定ではない**。どこを押しても同じ合図が飛ぶ | テレビの前で正確に狙わせるのは無理がある |

minifb は文字を出せないので、`fontdue` で自前で描いている。

## 操作の口

マウス・キーボード・テレビのリモコン・標準入力は、供給元が違うだけで意味は
同じ。**口は1つ（`kit::Control`）にまとめ、意味（`kit::Press`）だけを運ぶ。**

- ウィンドウとリモコンは、同じチャンネルへの送り手が2本あるだけ
- **送り手が全部落ちたこと（ウィンドウが閉じられた）が、そのまま終了の合図になる**
- 終わるための経路を別に用意しなくてよい

**リモコンは minifb では受けられない。** Bravia の決定ボタンは `KEY_OK` で
届くが、`minifb::Key` に OK が無いので Space / Enter にならない。だから
`cec.rs` が evdev を直に読む。何がどう届くかは `tools/cec-probe.sh` で見られる。

## 聞き取り

スピーカーから出た歌をマイクが拾う。エコーキャンセルには手を出さず、
問いかけが鳴り止んでから聞く窓の制御で避ける。

| つまみ | 既定 | していること |
| --- | --- | --- |
| `listen.guard_ms` | 200 | 窓を開けてからしばらくは判定しない。残響で誤発火しないため。録音は続くので、その間に話し始めても声は残る |
| `listen.preroll_ms` | 700 | 窓より前のぶんを遡って録音に残す。子どもは歌に被せて答えるので、頭が欠けないように |
| `listen.max_seconds` | 5.0 | 応答を待つ上限。声が途切れれば早く返す |
| `listen.hangover_ms` | 350 | 声が途切れてから打ち切るまでの猶予 |
| `listen.min_speech_ms` | 75 | これだけ続いて初めて「聞こえた」とみなす |

> [!NOTE]
> **`preroll_ms` は判定の窓を動かさない。** 声を拾ったとみなす時刻も
> `guard_ms` もそのままで、増えるのは録れている音だけ。

**入力ストリームは開きっぱなしにしてある。** 呼ばれるたびに開き直すと
デバイスの初期化に数百ミリ秒かかり、第一声を取りこぼす。

### 発話の判定

発話の判定はピークではなく RMS で見る。ピークだと単発のノイズに引っ張られる。

しきい値は、環境ノイズの `listen.speech_ratio` 倍を `speech_floor` と
`speech_ceil` で挟んで決める。部屋の静かさは環境で桁が違うので、固定値だと
誤発火か取りこぼしになる。

**環境ノイズは起動時に測って終わりではない。** 聞き取りのたびに更新する。
エアコンや外の音で部屋の底が動くため。

| 部屋が | 追従の仕方 | 理由 |
| --- | --- | --- |
| 静かになった | 即座に下げる | |
| うるさくなった | ゆっくり上げる | 逆にすると、話し声を環境ノイズと誤認する |

> [!TIP]
> **拾いすぎのコストはほぼゼロ。** 誤検出しても遊びが何かを鳴らすだけで、
> 何も聞こえなかったときと結果が同じ。迷ったら緩める側に倒す。

## 音声認識

whisper.cpp を `whisper-rs` 越しに使う。語彙は遊びが `Listener::hear` の
引数で毎回渡し、`initial_prompt` に並べる。漢字変換や言い換えを抑えるため。

### audio_ctx

whisper は入力を必ず30秒ぶん（= 1500）に詰めてからエンコードする。
`recognize.audio_ctx` を切ると、そのぶん計算量が落ちる。**目安は1秒あたり 50。**

既定の 0 は、実際に鳴った長さから毎回決める。「長さ × 50 + 1秒ぶんの余裕」を
128〜1500 に収めた値になる。2秒の返事なら 150 前後。使われた値は認識のたびの
ログに `audio_ctx N` と出る。

ラズパイ実測（音声 2.0〜2.3秒・大人の声）:

| `audio_ctx` | 認識 | 判定 |
| --- | --- | --- |
| 1500（切り詰めなし） | 2.79秒 / 2.72秒 | あか / ぜんぶ |
| 384（固定） | 0.66秒 / 0.78秒 | あか / ぜんぶ（同じ） |
| 0（長さから） | — | 150〜160 になる |

**パディングに情報は無いので、実長を覆う範囲なら精度は落ちない。** 落ちるのは
実音声より短く切ったとき。

> [!WARNING]
> 子どもの声で精度が出なかったとき、**モデルの大きさより `audio_ctx` のほうが
> 効いた**という別の実測がある。上の計測は大人の声で2回きり。子どもで外すなら、
> まず 768 → 1500 と固定して戻すこと。戻して切れることは無い。

### その他の速度設定

| 設定 | 値 | 理由 |
| --- | --- | --- |
| `n_threads` | 全コア | |
| `single_segment` / `no_context` | 有効 | 一言しか来ない |
| `max_tokens` | 5 | 答えは数トークンで終わる。暴走したときの復号を止める |
| 温度フォールバック | 無効 | 失敗したら判定の側に任せるほうが速い |

> [!IMPORTANT]
> **`max_tokens` は色当ての語彙から決めてある。** かな1文字と句読点がそれぞれ
> 1トークンで、正しい答えの最長は「むらさき。」の 5。長い答えを持つ遊びを
> 足すなら、ここを見直すこと（`io/listener/mic.rs`）。

それでも遅ければ、先に `paths.model` を tiny に落とす。`openblas` /
`openmp` も選べるが、**Pi 5 は素の NEON が既に速いので上積みは環境次第。**
`audio_ctx` を 1/4 にしたときとは桁が違う。

## カメラ

macOS では AVFoundation、ラズパイでは V4L2 を `nokhwa` 越しに使う。

| 決めごと | 理由 |
| --- | --- |
| **起動時に開く。1台も無ければ止める** | 選んでから気づくと、テレビの前で遊びが始まらない |
| 撮るのは、遊びが最初に `frame` を呼んでから `rest` まで | カメラを使わない遊びの間はランプを点けない |
| 名前が見つからなければ、警告して最初のカメラで続ける | マイクと同じ。起動しないほうが困る |
| 640×480 を MJPEG → YUYV → 何でも、の順に頼む | 縮めて 320×180 にするので、それ以上は復号の手間が増えるだけ |
| 撮るのは専用のスレッド。溜まった絵は最新だけ渡す | nokhwa の `Camera` はスレッドを跨げないうえ、1枚待つと 30ms 塞がる |
| 渡す前に左右を反転する | テレビを鏡として見せるため |
| 映像は保存も送信もしない | 子どもが映るため |

macOS では、初回にカメラの許可を聞かれる。ターミナルから動かすなら
ターミナルのアプリに、`.app` ならその `.app` に許可を出す。

## 音の口

`Player` の口は2本だけ。

| 口 | 呼び方 | 置き換え |
| --- | --- | --- |
| 曲 | `begin` | 前の曲を止めて置き換える |
| 効果音 | `effect` | 曲は止めない。前の効果音を置き換える |

`silence` は両方止める。

## 終了コード

遊びは別スレッドなので、`main` に見えるのはチャンネルの状態だけになる。
**ウィンドウとゲーム、どちらの失敗も拾って 1 を返す。** テレビに繋ぎっぱなしの
玩具は、systemd の再起動条件しか自分を直す手立てが無いため。

| 状況 | 終了コード |
| --- | --- |
| 遊び終えた / ウィンドウを先に閉じた | 0 |
| ゲームが失敗を返した / ウィンドウが失敗した | 1 |
| ゲームがパニックした | 1 |
