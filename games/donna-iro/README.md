# どんないろがすき？（`donna-iro`）

「どんな色がすき？」と呼びかけ、子どもが叫んだ色名を聞き取って、その色の
続きを歌う。テレビには色の丸を映す。歌はクレヨンの歌で、色は標準的な
クレヨン12色セットに揃えてある。

遊び全般の決まり（装置に触らない、無反応にしない、など）は
[`games/README.md`](../README.md) にある。ここはこの遊びに固有のことだけ書く。

## 進行

```
intro
  ↓
┌→ question            どんないろがすき？（ト長調）
│    ↓ 最大5秒待つ
│  <color>              その色の節（5小節・ト長調）
│    ↓
│  tail / tail-lead     節の最終小節。間奏へ向かうときだけ助走つき
│    ↓
│  bridge / interlude   insert_every 周に1回、交互に挟む
└──┘                    「ぜんぶ！」と言うまで無限ループ
     ↓「ぜんぶ！」
   finale               転調 → ぜんぶの節 → エンディング（色がシャッフル）
     ↓
   もう1回？             home の側で訊く
```

| 聞こえたもの | 鳴らす色 |
| --- | --- |
| 色名（化けていても） | 判定が一番近いとした色 |
| 何も言わなかった、1音だけ、質問の回り込みだけ | ランダムな色 |
| 「ぜんぶ」 | フィナーレへ |

> [!IMPORTANT]
> **「ぜんぶ」には倒れない。** 聞き取れなかったときの行き先は色だけで、
> 型（`Answer` と `Color`）で分けてある。何も言っていないのに終わることはない。

### 応答の窓

`question.wav` の末尾には、原曲の合いの手の枠が約1秒ぶん無音で入っている。
そこがまさに子どもが答える瞬間なので、**鳴り止んだ時点で窓を開ける。**
鳴らし切ってから聞き始めると手遅れになる。

**子どもは歌に被せて答える。** 「どんないろがすき」の「すき」あたりから言い
始めるので、録音は窓より `listen.preroll_ms` だけ遡って残す（[`home/README.md`](../../home/README.md#聞き取り)）。

## 判定

幼児の声は汎用 ASR が苦手。基本周波数が成人の2〜3倍あり、調音も不明瞭。
実際に「むらさき」が「村先」に、「ぜんぶ」が「じゃんぶー」に化けた。

対策は2段構え。

1. **語彙を whisper に教える。** 色名をひらがなで並べて `initial_prompt` に
   渡し、出力そのものを寄せる。漢字変換はここで止める。
2. **判定は位置を最優先に、段階的に見る**（`matcher.rs`）。

### 信用するのは先頭だけ

小さいモデルは短い音を渡されるとデコーダが暴走し、**言っていない語を後ろに
継ぎ足す。** tiny で試したとき、「あお」に対して「あお、おれんじ、あか」が
返った。しかも同じ語の繰り返しとは限らない。だから後ろは信用せず、先頭の
数区間しか見ない（`games.donna_iro.head_segments`、既定 2）。

> [!NOTE]
> **フィラーが1枠食う。** 「えー、みどり」だと「えー」で1つ使うので、
> 既定の 2 では色まで届くのがぎりぎりになる。増やすと届きやすくなるが、
> 後ろに継ぎ足す幻覚も拾いやすくなる。

### 段より位置を先に見る

先頭の区間から順に見て、当たった時点で決める。区間ごとの順は次のとおり。

1. 単独の完全一致
2. 単独の部分一致（長い読みから順に）
3. 次の区間と繋げたものの完全一致
4. 繋げたものの部分一致のうち、境目をまたぐもの
5. 音の近さ。単独と結合で距離の近いほう
6. 単独がどれにも当たらなければ、結合の部分一致と音の近さ

| こうしている理由 | 実際に起きたこと |
| --- | --- |
| 段を位置より上に置くと、後ろの完全一致が先頭を追い越す | 「みじろ、きいろ」が きいろ になった |
| 認識は語を割るので、繋げたものも見る | 「ちゃいろ」が「じゃあ、いろ」になった |
| 音の近さは、拗音と長音を落とした骨格で測る | 幼児の発音は「ぜ」が「じぇ」に、「ぶ」が「ば」に寄る |

**どの段にも当たらなくても諦めない。** 測った中で一番近い色へ倒す。足切りして
ランダムな色を鳴らすより、このほうが当たる。実機のログでも、段が諦めた場面で
子どもが実際に言った色が上位に居た。

### 回り込みを落とす

スピーカーから出た質問の歌がマイクに回り込む。「どんないろがすき」には
「いろ」が含まれるので、残したまま判定すると きいろ や しろ に化ける。

- 質問の文言は、判定の前に削る
- 区間まるごとが質問の一部なら、答えではなく回り込みとして捨てる

### 読みの持ち方

読みは色ごとにひらがなが1つ。漢字表記がある色は漢字も1つ持つ（`color.rs`）。
`initial_prompt` は誘導であって強制ではないので、漢字は出る（実際に「全部」が出た）。

表記ゆれを列挙する方式は追いつかない。標準形だけ持って、残りは部分一致に任せる。
「紫色」「真っ赤」は「紫」「赤」を含むので拾える。

> [!TIP]
> 精度が足りなければ、その子の声で学習した専用分類器に差し替える。
> `kit::Listener` に実装を1つ足すだけで入る。

## 画面

| 場面 | 映すもの |
| --- | --- |
| 質問・区切り | 全色の丸を並べる |
| 色の節 | その色の丸を1つ大きく |
| フィナーレ | 全色の丸を `flash_ms` ごとにシャッフル |

## つまみ

`config.toml` の `[games.donna_iro]`。値の意味と環境変数名はそちらに書いてある。

| キー | 既定 | |
| --- | --- | --- |
| `insert_every` | 3 | 何周に1回、ブリッジか間奏を挟むか |
| `flash_ms` | 500 | フィナーレで色を差し替える間隔（ミリ秒） |
| `head_segments` | 2 | 認識結果の先頭いくつの区間を信用するか |

どれも0は起動時に弾く。

## コード

| ファイル | 中身 |
| --- | --- |
| `src/color.rs` | 色の定義（読み・漢字・RGB・名前）と、子どもの応答 `Answer` |
| `src/cue.rs` | 鳴らす素材。文字列ではなく型で指す |
| `src/matcher.rs` | 応答の判定 |
| `src/play.rs` | 進行。`kit::Game` の実装と、装置なしの進行のテスト |
| `src/look.rs` | 映すもの。丸を並べる |
| `src/config.rs` | `[games.donna_iro]` の型と検査 |

色を足すときは `color.rs` の定義に1つ書く。素材名は変種名を小文字にしたもの。

## 素材

歌は**つくよみちゃんの音源**で、元譜面ごと private サブモジュール
[donna-iro-assets](https://github.com/mpyw/donna-iro-assets) に分けてある。
`games/donna-iro/assets/` にマウントし、Git LFS で持つ。

| 在処 | 中身 |
| --- | --- |
| `assets/*.wav` | 本番音源 |
| `assets/reference/*.wav` | MusicXML から機械的に鳴らした確認用の合成音 |
| `assets/musicxml/` | 素材ごとに切り出した MusicXML |
| `assets/score/` | 購入した元譜面 |

本番音源が揃うまでは `reference/` が鳴る。音源の切り方と書き出しのルールは
`assets/README.md` にある。

| ツール | |
| --- | --- |
| `tools/split_score.py` | 元譜面から素材ごとの MusicXML を切り出す。原曲に無い8色は節の型に合わせて編曲する |
| `tools/render_reference.py` | MusicXML から `reference/` の合成音を書き出す（numpy が要る） |

どちらもリポジトリの根から叩く。

> [!CAUTION]
> 曲も譜面も著作物なので、**サブモジュールは private のまま運用すること。**
